# 내가 적어둔 숫자는 그때의 숫자였다

지난 글이 9월 9일이고 지금 13일이다. 나흘 동안 한 일은 하나다. **Next.js를 14에서 16으로 올렸다.**

시작한 이유는 시시하다. `npm audit`에 취약점이 남아 있어서 없애고 싶었다. 목적은 달성했다. 지금은 0건이다.

그런데 올리고 나서 새 도구가 잡아준 게 더 컸다. **14에서는 조용히 넘어가던 것들이 세 개 있었고, 셋 다 실제로 배포되고 있었다.** 그 얘기를 먼저 한다.

## 1. 깨진 CSS가 몇 주째 배포되고 있었다

16부터 빌드 도구가 webpack에서 Turbopack으로 바뀐다. 올리자마자 빌드가 여기서 멈췄다.

```
app/globals.css:1535
.\[-\:\|\\s\] {
  -: |\s;
}
Unexpected token Semicolon
```

`-: |\s;`. CSS가 아니다. 저런 걸 내가 쓴 적이 없는데 왜 빌드된 파일에 있나 싶어서 거슬러 올라갔다.

범인은 마크다운에서 표 구분선을 걷어내는 정규식이었다.

```ts
// 표 구분선(|---|---|)이나 구분선(---)처럼 글자가 아닌 줄은 통째로 버린다.
.replace(/^[-:|\s]{3,}$/gm, ' ')
```

`[-:|\s]`. Tailwind는 소스 파일을 글자 단위로 훑으면서 클래스 이름을 찾는데, 이걸 **임의 속성 클래스**(`[color:red]` 같은 문법)로 읽었다. 속성 이름은 `-`, 값은 `|\s`. 그래서 저 규칙을 만들어냈다.

14의 postcss는 이걸 그냥 삼켰다. 문법이 깨진 규칙 하나쯤은 넘기고 나머지를 내보낸다. Turbopack의 파서는 거기서 멈춘다.

고치는 건 한 줄이었다.

```ts
// 글자 순서를 바꾼 이유: [-: 로 시작하면 Tailwind가 이걸 임의 속성 클래스로
// 읽고 깨진 CSS를 만든다. 바뀐 순서에서도 찾는 글자는 똑같다.
.replace(/^[\s|:-]{3,}$/gm, ' ')
```

문자 집합은 그대로고 순서만 바꿨다. 정규식이 찾는 건 똑같고, Tailwind가 오해할 모양만 사라진다.

**여기서 불편한 건 고치는 난이도가 아니다.** 이 깨진 규칙이 언제부터 배포되고 있었는지 내가 모른다는 것이다. 빌드는 성공했고, 화면은 멀쩡했고, 아무도 안 알려줬다. 도구를 바꾸지 않았으면 계속 그 상태였을 것이다.

## 2. 링크 미리보기 이미지가 만들어진 적이 없었다

빌드가 다음 지점에서 또 멈췄다.

```
Invalid value "120" for "height". Expected a number, "auto", or a percentage value.
Error occurred prerendering page "/opengraph-image"
svgload_buffer: SVG rendering failed
```

OG 이미지 — 카톡이나 슬랙에 링크를 붙이면 뜨는 그 카드 — 를 만드는 코드다. 로고를 이렇게 넘기고 있었다.

```tsx
<img width="120" height="120" alt="" src={...} />
```

문자열 `"120"`. satori(JSX를 SVG로 그리는 라이브러리)는 여기서 숫자를 기대한다. 숫자로 바꾸니 끝이었다.

```tsx
<img width={120} height={120} alt="" src={...} />
```

이건 앞의 것보다 더 민망하다. **나는 이 기능을 만들어놓고 결과물을 한 번도 확인하지 않았다.** 한글 폰트를 조각으로 받아오는 부분까지 신경 써서 만들었는데, 정작 이미지가 나오는지는 안 봤다. 14에서는 조용히 실패하고 넘어갔다.

## 3. "예약" 딱지가 시간이 지나도 안 없어졌다

16은 린트 규칙도 같이 올라온다. React 19용 규칙 18건이 새로 잡혔다. 대부분은 "이렇게 써도 돌아가긴 하지만" 쪽이었는데, 하나는 진짜 버그였다.

관리자 화면에서 발행 예정인 글에 "예약" 딱지를 붙이는 코드다.

```tsx
new Date(post.published_at).getTime() > Date.now() && <span>예약</span>
```

`react-hooks/purity`가 잡았다. 그리는 중에 시계를 읽으면 안 된다는 것이다. 처음엔 "여기는 관리자 화면이고 어차피 클라이언트에서만 도는데" 싶었는데, 규칙이 옳았다.

**예약 시각이 지나도 그 딱지가 안 없어진다.** 화면이 다시 그려질 이유가 없기 때문이다. 관리자 화면을 열어두고 있으면, 이미 발행된 글이 계속 "예약"이라고 표시된다.

시계를 바깥 값으로 두고 구독하게 바꿨다.

```ts
export function useNow(intervalMs = 60_000): number {
  const subscribe = useCallback(
    (onChange: () => void) => {
      const id = setInterval(onChange, intervalMs);
      return () => clearInterval(id);
    },
    [intervalMs]
  );

  // 간격 단위로 끊어서 낸다. 밀리초를 그대로 내면 부를 때마다 값이 달라져
  // React가 끝없이 다시 그린다.
  const read = useCallback(
    () => Math.floor(Date.now() / intervalMs) * intervalMs,
    [intervalMs]
  );

  return useSyncExternalStore(subscribe, read, () => 0);
}
```

`getSnapshot`은 부를 때마다 같은 값을 내야 한다. `Date.now()`를 그대로 돌려주면 매번 다른 값이라 React가 "또 바뀌었네" 하면서 무한히 다시 그린다. 분 단위로 끊으면 1분 동안은 같은 값이다. 딱지가 최대 1분 늦게 사라지는 건 감수한다.

나머지 17건 중 열 개는 "마운트 후에 오늘 날짜를 채우는" 패턴이었는데, 세어보니 관리자 편집기 다섯 곳이 똑같은 걸 들고 있었다.

```tsx
const [startedOn, setStartedOn] = useState('');

useEffect(() => {
  // 서버와 브라우저의 시간대 차이를 피하려고 마운트 후에 채운다.
  setStartedOn(toDateKey(new Date()));
}, []);
```

주석이 말하는 위험이 **이 화면에는 없었다.** 관리자 페이지는 로그인 확인이 끝난 뒤에야 편집기를 그린다. 서버에서 그려지는 건 "확인 중..." 한 줄뿐이라 시간대가 어긋날 자리가 애초에 없다. 한 줄로 줄었다.

```tsx
const [startedOn, setStartedOn] = useState(today);
```

`useState(today)` — 함수를 그대로 넘기면 첫 그리기 때 한 번만 불린다. 복사-붙여넣기로 퍼진 방어 코드가 다섯 군데에서 사라졌다.

## 4. 그리고, 같은 교훈을 또 배웠다

여기까지가 버전 올린 이야기다. 이 다음이 진짜 하고 싶은 얘기다.

바뀐 게 많으니 확인을 해야 했다. Supabase 흉내만 내는 서버를 하나 띄워서 26개 경로를 전부 브라우저에 그려봤다. 그러면서 접근성 검사도 같이 돌렸다.

**4건이 잡혔다.**

- 지도 핀에 이름이 없다 — 화면 낭독기로는 전부 그냥 "버튼"으로 읽힌다
- 지도 틀에 `role="img"`가 붙어 있는데 그 안에 누를 수 있는 핀이 들어 있다
- 어두운 테마에서 "지도를 불러오지 못했어요" 문구가 안 읽힌다
- `/activities`의 연도 제목이 h1 다음에 바로 h3다

넷 중 둘은 **내가 직접 만든 것**이다. `role="img"`는 내가 붙였다. 핀 이름도 내가 붙인다고 붙였는데, Leaflet의 `divIcon`이 `alt` 옵션을 그냥 버린다는 걸 몰랐다.

```ts
L.marker([lat, lng], {
  icon,
  alt: `${trip.place}, ${countryName(trip.country_code)}`,  // 조용히 버려진다
})
```

문제는 이게 아니다. **나흘 전 글에서 나는 이렇게 썼다.**

> ## 2. 접근성 100점은, 두 페이지 점수였다
> 그 뒤로 지도, 복무 상태 배지, 이력서를 붙였다. 그 100점이 아직 맞는지 확인한 적이 없었다.

그 글에서 11개 페이지를 라이트·다크로 훑고 위반 0을 만들었다. 그리고 **그 뒤에 지도를 손봤다.** 타일 판을 바꾸고, 핀을 다시 그리고, 공개 화면에도 지도를 붙였다. 그러고서 다시 재지 않았다.

똑같은 실수를, 그걸 교훈이라고 적은 글을 쓴 지 나흘 만에 했다.

### 그래서 뭘 바꿨나

교훈을 또 적는 건 소용이 없다는 게 이번에 얻은 것이다. 나흘 전에도 적었으니까.

**숫자를 글에 적는 대신 검사를 코드에 두는 쪽이 맞다.** 이 저장소에는 이미 그런 게 하나 있다. 코드 주석에 존댓말이 섞이면 테스트가 깨진다.

```ts
it('코드 주석에 존댓말이 없다', () => {
  // ... 저장소 전체를 훑는다
  expect(offenders).toEqual([]);
});
```

이건 내가 잊어버려도 돌아간다. 접근성 검사도 그 자리로 가야 한다. 지금은 내가 기억날 때 손으로 돌리는 스크립트라, 기억이 안 나면 안 돌아간다. 나흘 전에 그걸 증명했다.

**그런데 이건 주석 검사처럼 간단하지가 않다.** 주석 검사는 파일만 읽으면 된다. 접근성 검사는 페이지가 실제로 그려져야 하고, 페이지가 그려지려면 데이터베이스가 필요하다. CI에는 진짜 키가 없다 — 빌드만 통과시키려고 가짜 값을 넣어둔다. 그 상태로 띄우면 글 목록도 여행 지도도 전부 오류 화면이 된다. **오류 화면에는 접근성 위반이 없다.** 통과했다는 초록 불만 뜨고 아무것도 안 본 검사가 된다.

이번에 확인하면서 Supabase 흉내만 내는 서버를 하나 만들어 썼는데, 그걸 CI에 넣는 게 답인 것 같다. 가짜 데이터로라도 페이지가 그려져야 검사할 게 생긴다.

**아직 안 했다.** 다음 글에서 했다고 쓰게 되든 또 안 했다고 쓰게 되든, 그건 그때 적겠다. 나흘 전 기록을 보면 후자일 가능성도 충분하다.

## 5. 덤: 코드가 좀 줄었다

확인하면서 눈에 걸린 것 두 개를 같이 정리했다.

**지도가 두 벌이었다.** 공개 화면의 여행 지도와 관리자의 좌표 고르기가 지도를 세우는 부분을 통째로 각각 들고 있었다. 라이브러리를 늦게 불러오고, 타일을 얹고, 테마를 따라 판을 갈아끼우고, 나갈 때 치우는 것까지 글자가 같았다. 다른 건 지도 위에 뭘 그리느냐뿐이라 그것만 넘겨받게 했다.

```ts
return mountMap(box, {
  scrollWheelZoom: false,
  onTilesFailed: setTilesFailed,
  draw: (L, map) => {
    // 여기만 다르다
  },
});
```

합치니 관리자 쪽도 타일 실패를 말하게 됐다. 공개 화면에만 있던 안내였는데, 타일이 안 오면 빈 판만 남는 건 양쪽이 똑같다. **좌표를 고르는 화면에서 오히려 더 나쁘다.** 누를 자리가 안 보이니까.

**편집기 하나가 또 옛날 코드였다.** 여섯 중 다섯은 공용 훅을 쓰는데 일정 편집기만 자기 목록·저장·삭제를 따로 들고 있었다. 열어봤더니 이게 있었다.

```tsx
if (!error && data) setEvents(data as CalendarEvent[]);
```

```tsx
await supabaseClient.from('events').delete().eq('id', id);
```

조회가 실패하면 "일정 없음"으로 보이고, 삭제가 거절돼도 아무 말이 없다. **지난 글에서 `PostEditor`를 두고 똑같은 얘기를 썼다.** 그때 "고쳤다는 파일 단위가 아니라 패턴 단위로 확인해야 한다"고 적었는데, 그러고도 나머지를 안 셌다.

이번에는 셌다. 여섯 개 중 여섯 개가 같은 훅을 쓴다.

---

나흘 동안 새로 만든 기능은 없다. 버전 하나 올렸고, 그 김에 세 개를 고쳤고, 같은 실수를 두 번째로 했다는 걸 알았다.

버전 올리기를 미루는 이유가 보통 "지금 잘 돌아가는데"인데, 이번에는 **잘 돌아가는 것처럼 보였던 것**이 세 개 나왔다. 도구를 바꾸면 도구가 보던 것도 바뀐다. 그게 이번의 수확이다.
